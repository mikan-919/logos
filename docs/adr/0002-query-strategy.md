# ADR-0002: クエリ戦略

## ステータス
提案中

## 背景
「`GithubIssue` のstatus=openなEntityを取得する」のようなフィールドレベルのフィルタをどう表現するか。

## 決定
当面は以下の2つのアプローチを取る：

1. **Component型でフィルタ** — `[{type: "GithubIssue"}]` のようなComponent型ベースのクエリ
2. **全件ロード** — フィールドレベルの条件が必要な場合はクライアント側でフィルタ

フィールドレベルの条件が頻出する場合は、条件をComponentとして表現することを検討する。

## トレードオフ
- **利点:** REST APIをシンプルに保てる。GraphQLの複雑なスキーマ管理が不要
- **欠点:** 全件ロードは負荷が高い。データ量が増えると現実的でなくなる

## 将来の検討
負荷が問題になった時点でクエリ言語の導入またはGraphQL移行を検討する。
