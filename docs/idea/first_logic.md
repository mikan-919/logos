概念上同じものを同じとして管理するデータベース設計。
例えば、linearで管理しているissueがあって、LinearとGithubIssueのどちらもPluginできるサービスがあった時、同じタスクなのに、それらが別物として扱われるのはおかしい。
実際にはそれらは同じ概念の異なる表現に過ぎない。
ならばツールを中心に管理するのではなく、概念(Entity)を中心に管理すべきではないか。
これらをECSのEntity,Componentのアイディアから使って、同じものを同じEntityとして扱うことで、概念上同じものを同じとして管理できるようにする。
また、同じ概念あるいは事柄の異なる側面をComponentとして表現することで、複数のプロダクト間でデーターを実質的に共有、あるいは見え方の変化として表現できる。
例えば、タスクに知識をタグづけてしてそれをNotionのページとして書くとか。
